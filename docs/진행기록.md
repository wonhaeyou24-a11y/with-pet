# 진행 기록

## M1 (부화) — 구현 완료, 폰 확인 전

### 결정 사항
- 몬스터 그림: 시안(`design/characters/`)은 분위기 참고용이고, 종족 6종은 레이어 SVG로 새로 디자인했다 (`src/monsters/`). 몽실은 단독 파일, 나머지 5종은 공용 틀(`Biped.tsx`)에 종족별 귀·꼬리·머리 장식 4종씩과 특징 부품을 끼운다.
- 외형은 서버가 부화 때 숫자(팔레트, 체형, 크기, 귀·꼬리·장식 번호, 눈매, 무늬 시드)로 정해 `monsters.parts`에 저장하고, 화면이 그림으로 바꾼다. **이미 부화한 몬스터가 있으면 부품 번호의 의미를 바꾸지 않는다** (모양을 다듬는 것은 괜찮음).
- 번개꼬리는 시안이 피카츄와 닮아서 민트색 족제비 + 수정 번개 꼬리로 새로 디자인했다.
- 몬스터 이름은 한 번 정하면 바꿀 수 없다 (한글·영문·숫자 1~10자, DB 트리거로 강제).
- 쓰다듬기 -3분, 따뜻하게 하기 -5분, 각각 하루 5회 (한국 시간 기준 날짜). 쓰다듬기는 성격을 응석 쪽으로, 따뜻하게 하기는 차분 쪽으로 민다. 알은 M1에서 일반 등급 1개만 지급한다.
- 기본 알은 닉네임을 정한 뒤 처음 접속할 때(`egg` 함수의 `sync`) 서버가 한 번만 지급한다.

### 만든 것
- DB: `supabase/migrations/20261029100000_m1_eggs_monsters.sql` (eggs, monsters, RLS, 이름 한 번만 바꾸기 트리거)
- 서버 함수 `egg` (`supabase/functions/egg/`): sync, pet, warm, hatch. 수치는 `config.ts`, 결과 굴리기는 `roll.ts`
- 화면: 로그인·코드 입력·닉네임·알(대기/부화 가능)·부화 연출·이름 짓기·몬스터 홈·몬스터 상세
- 개발용 확인 페이지(운영 빌드에는 안 들어감): `#/dev/monsters`(종족 그림), `#/dev/screens`(전체 화면 가짜 데이터)

### 남은 것
- 폰으로 부화까지 확인 (테스트하려면 `config.ts`의 `hatchMinutes.common`을 1로 줄여 다시 배포)
- 알 등급 희귀·전설의 지급 경로는 M2 이후 (그림은 `EggArt`에 준비됨)
- 폰트는 시스템 한글 글꼴을 쓴다 (Pretendard 자체 호스팅은 나중에)

## M0 (준비) — 완료

### 결정 사항
- 게임 이름: **펫과함께** (임시 이름 아님, 우선 이 이름으로 시작)
- 로그인: 이메일 6자리 코드 (OTP). 아이폰 홈 화면 앱에서 매직링크가 안 넘어오는 문제를 피하기 위해 링크 대신 코드 입력 방식.
- 가입: 초대 코드 필수. `redeem-invite` Edge Function이 코드를 선점하고 계정을 만든다. Supabase 대시보드에서 "Allow new users to sign up"을 꺼서 다른 경로의 가입을 막는다.
- `players`의 코인·별조각·랭크 점수는 클라이언트가 쓸 수 없다 (컬럼 권한으로 닉네임만 허용).
- 기획서 원본은 `docs/몬스터 육성 게임 기획서.docx`, 변환본이 `docs/기획서.md`.
